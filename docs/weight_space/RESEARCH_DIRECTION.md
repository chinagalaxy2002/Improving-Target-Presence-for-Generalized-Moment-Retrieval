# SoccerGMR：以因果诊断驱动存在性权重修复

更新：2026-11-03。状态：研究方向与下一轮实验计划，不是已验证的新方法。

## 1. 工作目标与当前判断

**研究问题：当原生模型已给出正确的 Top-1 时间区间时，GEQ 是否存在可定位、可因果验证、可通过少量权重修改移除的错误拒绝机制？**

工作主线定为：**在固定定位能力下，沿 GEQ 的证据读取过程定位错误拒绝的来源，再将有效的激活干预编译为小规模、无梯度的权重编辑。**

下一轮优先补齐机制诊断，不再把扩大终端分类头方向搜索作为主要工作。现有结果说明：开发集上可找到改善，但尚无稳定的 Val FN-Loc 挽救证据。这里的“模型具有定位能力”不能直接推出“GEQ 已具有存在性判别能力”；两者读取和使用的证据可能不同。这是需要实验区分的两个解释。

本轮实际对象为历史 **FlashVTG E1 / epoch 4**。代码放在 `soccergmr-standard-geq-full` 分支，运行时显式使用历史 `JointGMR`，不把它表述为当前分支十轮早停协议训练出的模型。E1 不是初始 GMR baseline，修复参照必须是未编辑 E1 自身。

## 2. 博客中最相关的内容

来源：[Takehi 等，Sparks of Weight-Space Programming，2026-11-02](https://rikiyat.github.io/blog/weight-space-programming/)。以下是简要转述；博客报告尚不能替代我们的验证。

- **实验 8：定位再编辑。** 作者报告将循环行为追踪到特定 MLP 输出方向，并修改少量输出列。对我们的启发是先验证故障来源，再动权重。[原文](https://rikiyat.github.io/blog/weight-space-programming/#:~:text=Experiment%208)
- **实验 7：需要内部证据。** 单看权重未能可靠区分行为；加入注意力观测后才成功。我们因此应检查 GEQ 实际读取了什么。[原文](https://rikiyat.github.io/blog/weight-space-programming/#:~:text=Experiment%207)
- **Gemma 失败案例：存在适用边界。** 作者未找到可移除的统一故障，编辑收益未成立。我们也应允许“缺少判别能力”这一结论。[原文](https://rikiyat.github.io/blog/weight-space-programming/#:~:text=Raising%20math%20capability)

### 我们如何借鉴

| 博客启发 | 我们的具体转化 | 必须避免的推断 |
|---|---|---|
| 追踪异常组件 | 对每一层 GEQ 记录读取结果、残差、FFN 输出及其对最终 logit 的影响 | 一条均值差方向能区分样本，不代表它是故障原因 |
| 用内部观测辅助解释 | 检查文本读取、视频读取和 FFN 分别在哪里改变存在性证据 | 注意力集中在某处，不代表该处导致决策 |
| 激活干预后修改输出列 | 先测试层内干预，再生成数学等价的列编辑 | 将最终分类头空间的方向直接用于所有中间层，默认其语义相同 |
| 保留失败案例 | 将无法泛化、产生副作用、无法转成固定权重的方案作为明确失败类型 | 把任意 AUROC 微涨或一次挽救写成方法有效 |

我们的几何方向、协方差求解和稀疏筛查属于数据驱动的解析编辑探索，不等同于博客展示的 LLM 直接推理权重，也不能因此声称复现了博客方法。博客提供的是研究路线启发。

## 3. 已有证据与它支持的判断

实验文件：[第一轮](../../scripts/weight_space/README.md)、[扩展实验复现](../../scripts/weight_space/EXPLORATION.md)。完整结果保存在工作区外的独立实验目录，见末尾索引。

| 实验 | 开发组发现 | Val 结果 | 当前判断 |
|---|---|---|---|
| B–C 分类头均值方向 | 一些强度能挽救 FN-Loc，但伴随其他正查询误拒或空查询误接收 | 未形成可保留的稳定收益 | B 与困难空查询之间的差异不足以保护 A、D |
| 588 个解析分类头干预 | 30 个满足开发组约束；预选 8 个不同方向族 | 暂选的 16 维稀疏编辑 FP 9→13，G1@0.5 51.94→50.54 | 开发组改善没有泛化，不能在 Val 中再挑赢家 |
| GEQ 第 1 层 FFN，32 列，强度 0.5 | 挽救 1 条 FN-Loc；FP 22 不变，FN 562→561 | FN-Loc 挽救为 0；FP/FN 不变；AUROC 0.69968→0.70075 | 干预可以编译为实际权重，但行为收益证据不足 |
| 同层强度 1.0 | 同样挽救 1 条 | FN-Loc 挽救为 0；AUROC 0.70176 | 不能因 Val AUROC 较高而改选此强度 |
| 其他层/列干预 | 已测试方案没有通过开发组因果门槛 | 未据此生成对应 FFN 编辑 | 仅排除了这些具体干预，不能排除整层的作用 |

FFN 激活干预与实际权重编辑的概率差异小于 1.2×10⁻⁷，验证的是**实现等价性**；它不是修复效果或机制唯一性的证明。当前 native 张量一致性检查支持定位路径未改变；固定候选官方评估的 mAP 均为 28.15。

另外，Val 已被多轮查看。后续继续查看时应标为复用的诊断集，不能重新命名为从未接触的确认集。固定 E1 训练本身也使用过 Standard Train；“未参与方向发现的视频”只表示对编辑构造过程隔离。

## 4. 三个竞争性解释

| 假设 | 可观察预测 | 能削弱该解释的结果 | 优先诊断 |
|---|---|---|---|
| H1：读到了证据，但终端决策边界不合适 | 终端表示中的目标证据稳定；简单 head 编辑能跨视频改善，且不伤害正确接受和空查询 | 只有开发组收益、强度稍变就增加错误，或效果等同 bias 调整 | 保留现有 head 方法作为廉价对照 |
| H2：读取/残差更新引入了错误抑制 | B 在某个 GEQ 子步骤出现可重复的证据下降；小范围激活干预能恢复决策并保护其他类别 | 只能靠替换整个正样本状态才恢复，或恢复与样本标签无关 | **下一轮主线**：层内追踪与必要性/充分性干预 |
| H3：GEQ 缺少区分存在与空查询的能力 | 正确定位候选仍存在，但 GEQ 表示和干预反应无法稳定区分 B 与匹配空查询 | 找到跨视频复现、低副作用且可编辑的局部组件 | 作为应保留的研究结论；不能靠无限搜索掩盖 |

三者不是预先认定的结论，也可能按查询类型并存。尤其不能仅凭 head 搜索失败就判定 H3 成立。

## 5. 下一阶段：从证据流到可编辑组件

### 5.1 建立逐查询证据轨迹

在历史 E1 中提取：初始 token、text_read 前后状态、各 video_read 的 attention 输出、残差相加结果、LayerNorm 前后状态、FFN 中间激活与输出、最终 head 输入和 logit。保存 qid、视频、查询、GT、原生候选和全部干预位置。

每个中间状态用原 head 做投影，只能作为“方向性探针”，不能称为该层已校准的存在性概率。额外用移除该分支后的**真实最终 logit 变化**量化分支效应，避免把投影解释成因果结果。

样本继续包括 A、B、C、D，并保留 Top-1 IoU<0.5 的正查询。匹配比较优先控制事件类型、候选相关性、视频时长和多目标数量；同视频配对用于机制分析，所有配对、donor 和目标视频都必须留在对应 discovery 折内。

诊断输出是一组具体命题，例如“B 在 video_reads.1 的 FFN 更新后最终 logit 下降，但匹配的 A 不下降”，而不是先指定要删哪些列。

### 5.2 用干预区分相关性与因果作用

对每个有证据支持的命题，依次做以下实验：

1. **必要性**：移除或缩小该分支输出，观察目标误拒是否减少；同时检查 A、C、D 和定位失败正查询。
2. **充分性**：在匹配 A 中加入被怀疑的分量，检查是否诱发错误拒绝。随机方向和匹配幅度干预必须同时运行。
3. **状态修复上界**：用 discovery 中匹配 A 的局部状态替换 B 对应状态，检查是否能恢复。带 GT 的 donor patch 仅用于诊断，不是部署方法；大范围替换成功也不能证明某个特定方向正确。
4. **跨视频复现**：冻结组件和方向，在未参与构造的 Train 视频折上重复上述效应。

仅有注意力图变化、均值分离或单次决策翻转，不能通过机制门槛。应报告 effect size、样本数和所有新增错误。

### 5.3 生成层内方向，避免直接搬用终端方向

优先从被定位子步骤的匹配状态差异构造局部方向，并与该层的权重列、激活幅度及分支效应交叉核验。LayerNorm 和后续读取会改变干预的传播，因此不能默认同一个 256 维方向在不同层具有相同含义。

对 FFN 输出投影 W、单位方向 u、选定列集合 S，先验证激活干预：

```text
Delta_y = -alpha * u * (u^T W[:, S] a[S])
```

再将其编译为固定权重：

```text
W'[:, S] = W[:, S] - alpha * u (u^T W[:, S])
```

同一输入下两者必须数值一致。方向、列集合和强度只能由 discovery/开发组决定。不能用每条查询的 GT 决定部署时的修改。

第一优先级为已有工具支持的 FFN 输出列；第二优先级为有因果证据的 attention 输出投影。token、attention Q/K/V 或归一化参数的修改，只有在证据指向它们时才另开小实验，不同时扩张所有参数族。

## 6. 数据使用与有限搜索协议

**立即停止根据复用 Val 反馈调整方向。** 下一轮先在 Standard Train 内冻结按视频分组的交叉验证协议：方向/列选择只看外层训练折，强度只看其中的开发折，外层折仅评估。所有预处理、候选分数分位点、PCA、协方差和 donor 选择均须在折内重算。

这能评估编辑构造过程对视频划分的敏感性，但由于既有探索已查看 Train，不能声称得到全新的确认数据。Val 仅在一个冻结版本之后统一报告。Standard Test / Full Test 继续封存；只有方法、超参数和选择规则全部冻结后，才另行安排最终评测，绝不以 Test 结果回调。

下一轮建议预算（预先写入 manifest，不是已执行配置）：

| 阶段 | 预算 | 通过条件 |
|---|---|---|
| 证据轨迹 | 3 个可证伪的机制命题 | 每个命题写清组件、样本条件和预期效应 |
| 激活因果测试 | 每个命题至多 4 个预定干预，共 12 个 | 跨视频方向一致，目标改善且副作用可控 |
| 实际权重编辑 | 至多 4 个机制候选，强度至多 3 档 | 先过激活门槛，再过编译等价和定位不变性 |
| 对照 | 每候选至少 bias、完整差异范数匹配随机编辑、无编辑 | 同数据、同预算；FFN 候选须有同层同列预算的随机对照 |
| 统一报告 | 全部候选、全部失败 | 冻结选择后一次性报告复用 Val，不事后改口径 |

过去 588 次筛查已是一个较大的开发搜索过程。下一轮预算应约束**机制假设数量**，而非把许多隐含试验算成一个“前向”。同时记录查询前向数、激活干预次数、权重候选数、耗时和显存，不直接套用博客的前向计数。

## 7. 评价与保留标准

主要目标仍是固定阈值 0.5 下的 FN-Loc 修复。必须同时报告：

- 原始 FN-Loc 中被挽救的比例和 qid；原本 A 类中新增误拒的比例和 qid；二者的净变化。
- 全部正查询的 TP/FN、全部空查询的 FP/TN，以及 C、D 分层误接收率。
- τ=0.4/0.5/0.6 的 G-mIoU@1/@3、三点均值、AUROC；阈值不作为额外搜索自由度。
- 参数数量、相对 GEQ 和全模型的比例、差异 L2/Frobenius 范数、运行成本。
- 按视频做配对 bootstrap 的不确定性；交叉验证各折的分布，不只给聚合均值。

开发组硬门槛延续“FP、总 FN、困难空查询误接收不增加”，并新增“正确定位正查询的净收益为正”，防止用挽救其他正查询来遮盖 A 类伤害。最终是否声称有效，还需预注册的最小效应要求和不确定性支持；1 条开发组挽救、Val 0 条不能作为成功。具体最小效应数值应在下一轮评估前写定，不能看到结果后调整。

**工程硬门槛独立于行为门槛**：只改 `geq.*`；原始 checkpoint SHA 不变；同输入下 native 所有张量精确相同；候选区间、顺序与分数一致；官方 mAP 一致；激活干预与实际权重编辑数值一致。任何一项失败先归类为实现问题。

### 候选分数融合的明确边界

历史 FlashVTG 导出会让 GEQ 分数缩放候选分数。当前实验通过参照原始 E1 的推理桥接固定候选导出，再替换存在性决策。文档必须同时写明：

1. 原生定位网络不变；
2. 固定候选协议中的定位导出和 mAP 不变；
3. 这并不意味着把编辑 checkpoint 直接塞入未经桥接的历史导出流程，候选分数仍自动不变。

实验报告不能把第 2 点扩张成第 3 点。官方指标代码和原生模型结构继续保持原样。

## 8. 可形成的研究逻辑与当前缺口

暂定位为技术路线探索：将因果权重修复用于固定定位条件下的存在性误拒。尚未核验该设定的文献新颖性，不将其写成“首次”。

| 逻辑环节 | 内容与对应工作 |
|---|---|
| 背景 | 足球片段检索中，正确时间候选仍可能被存在性门控拒绝 |
| 局限 1 | 我们的终端方向筛查不能稳定保护正确接受和普通空查询 |
| 局限 2 | 我们目前的中间层修改能实现因果等价，但行为效应很小且不泛化 |
| 局限 3 | 多轮开发/Val 查看增加了选择偏差，单条挽救不足以支撑结论 |
| 关键想法 | 先定位跨视频复现的错误证据更新，再将经过因果验证的局部干预转成固定 GEQ 权重 |
| 挑战 1 → 模块 A | 区分错误抑制与证据不足 → 匹配查询的逐层证据诊断 |
| 挑战 2 → 模块 B | 控制方向传播和类别副作用 → 层内因果干预及等价权重编辑 |
| 挑战 3 → 模块 C | 约束搜索偏差与定位代价 → 视频分组验证、对照与不可变性审计 |
| 拟验证贡献 1 | 诊断模块能否识别可复现的误拒来源；对应未来“问题分析”部分 |
| 拟验证贡献 2 | 因果干预能否得到跨视频有效的小规模编辑；对应未来“方法”部分 |
| 拟验证贡献 3 | 能否以完整对照界定编辑的收益、代价和适用边界；对应未来“实验”部分 |

四项逻辑检查：局限→关键想法、关键想法→挑战、挑战→模块，在计划层面均能对应。模块→贡献仅为**待验证目标**，不能算完成。当前主要缺口是机制复现与泛化效果（MAJOR），以及文献新颖性核验（MAJOR）；尚未形成已被证据支持的有效方法贡献。没有必要在这一阶段起方法名称或写强结论 Introduction。

## 9. 下一次工作应交付什么

先交付一份逐层证据诊断，回答“哪一类 B、在哪一个组件、发生什么改变、与哪些匹配 A/C/D 不同”。随后只针对最多三个证据充分的命题实施必要性和充分性测试。若没有可复现局部机制，应收束为当前权重空间不可可靠修复的负结果，或另行讨论允许训练/改变结构的新项目；不能在原约束下悄悄改变目标。

每个命题建立单独目录，包含 `hypothesis.md`、视频划分与数据哈希、原始轨迹、因果干预记录、候选 manifest、对照、qid 变化及保留/拒绝理由。现有 CLI 继续作为基础，但“层内证据轨迹”和“匹配 donor 的双向干预”属于**尚待实现**的能力。
