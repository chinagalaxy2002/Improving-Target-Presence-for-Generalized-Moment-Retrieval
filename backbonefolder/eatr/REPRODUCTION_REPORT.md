# EaTR deployment report

Status: TRAINING. Published results have not yet been reproduced or compared; user permits handoff once training starts.

Official upstream: https://github.com/jinhyunj/EaTR at commit `384f09396a32741a73106d2e147bde54cbcce48f`, retrieved through GitHub API archive. `source_manifest.json`, the immutable archive, and `upstream_changes.patch` record source provenance and local modifications. Existing upstream checkpoint is QVHighlights; this Soccer-GMR run starts from scratch.

The official GMR repository contains no complete EaTR adapter implementation. The GMR variant is a local reconstruction of paper Section 4.1: max pooling over the final decoder slots, hidden256->256 ReLU->1 two-layer MLP, BCEWithLogits coefficient1, and existence score used by the official evaluator at threshold0.4. Native EaTR localization losses operate on positive examples only for GMR; original EaTR keeps native foreground/background supervision on every example, including natural negatives. Empty matched span losses return differentiable zero; empty accuracy is defined as zero to avoid division by zero. EaTR event attention, slot attention, pseudo-event discovery and native event loss remain intact.

Both variants retain all Standard examples and all annotated moments. Inputs use normalized SlowFast2304 then CLIP512 then native TEF2; CLIP text512 has max32 tokens. Released video representations use stride2 seconds, max75; frames were sampled1fps upstream. Native EaTR configuration is preserved: batch32, eval50, epochs200, StepLR drop150, AdamW weight decay1e-4, gradient clip0.1, encoder3/decoder3/hidden256/queries10/slot iterations3, original loss coefficients and auxiliary losses. Paper override learning rate3e-5 and seed2026. Python, NumPy, torch, CUDA and DataLoader seeds are recorded; no QCD, Query Swap, synthetic negative generation, background replacement or text masking is enabled. Soccer labels lack saliency annotations, so native saliency criterion returns zero, consistent with its missing-label branch.

Both smoke tests passed: positive and naturally negative examples, forward/backward, finite losses/gradients and nonzero gradients, optimizer step, full configured batch32, strict checkpoint reload, validation prediction schema and official evaluation. Original peak allocated679.0MiB; GMR683.2MiB. `original/smoke.json` and `gmr/smoke.json` contain evidence. Training reservation3000MiB allows padding/evaluation overhead.

Shared scheduler job `eatr-train-seed2026` runs physical GPU0 as a child of persistent tmux `table2_scheduler_20261022`. Runner performs original first, then GMR sequentially. Training actually passed epoch1 step100 with finite losses at handoff; PID is discoverable from shared scheduler registry. `train.log` records progress. The existing source directory is isolated from other backbones; shared data/features remain read-only.

Validation positive-query mAP selects best checkpoint. No test split is loaded until checkpoint SHA256 and threshold0.4 are frozen. Test inference and pinned official `evaluate_gmr` run automatically after training each variant, saving predictions/metrics. Last checkpoints include optimizer/scheduler and Python/NumPy/torch/CUDA/DataLoader generator state for safe resume.

Before judging reproduction, use a diagnostic tolerance of absolute2percentage points on mAP, mR@1, mR@5, mR+@5 and G-mIoU; AUROC and Rej-F1 must also be inspected, and agreement alone does not prove reproduction. Targets [AUROC,Rej-F1,mAP,mR@1,mR@5,mR+@5,G-mIoU@1,G-mIoU@3]: original [70.99,0.80,18.48,11.69,25.27,11.81,12.94,6.67], GMR [79.11,62.10,18.56,12.78,24.43,13.97,37.89,31.95]. Unreleased Soccer-specific EaTR configuration and missing saliency labels remain documented sources of uncertainty.
