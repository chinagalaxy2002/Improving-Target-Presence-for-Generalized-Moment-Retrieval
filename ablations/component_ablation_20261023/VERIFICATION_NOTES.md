# Candidate-dependency verification

An initial QD-DETR check using two CPU threads hit a bitwise-inequality assertion between separate forwards. The initial failure did not record its numerical magnitude. Its traceback is retained in `verify_fusion_final.log`. Isolated repeated forwards with and without candidate perturbation did not reproduce the inequality, and input feature tensors were unchanged (`debug_qd_invariance.py`). Two-thread and single-thread QD logits can differ in the final float32 bit; the check must control runtime conditions as well as candidates.

The final procedure uses one CPU thread, identical capture hooks in both arms, three no-op control forwards, and three candidate-perturbation forwards. It retains the strict bitwise-equality assertion for minusFusion and also requires the fusion-enabled diagnostic to respond to candidates. It does not relax numerical tolerances to pass the proposal-free check. Native fusion outputs are separately compared with the complete reference verifier equation. All final results are written to `reports/*_FUSION_BEHAVIOR.json` with both sets of repeated differences.

This change affects verification only. Training code, saved checkpoints, predictions, thresholds, and the formal 30 / additional 5 classification are unchanged. The initial failed check is not counted as a passed verification.

The raw-prediction audit initially enforced positive width on every exported window. That is stricter than the native FlashVTG export protocol: its archives retain zero-width candidates. The audit now requires finite coordinates and nonnegative width, records native zero-width windows, checks the official G-mIoU cleaner, and recomputes each metric under the unchanged official code. Raw predictions, ranking, and scores are not altered. This distinction matters because localization metrics and G-mIoU handle raw top-K windows differently.

The candidate-list audit initially required final submitted arrays to be identical between the frozen baseline and global-query-only model on every backbone. FlashVTG's original inference code multiplies candidate confidences by a presence-dependent factor before three-decimal rounding/NMS. Its raw `pred_relevant_windows_pre_exist` arrays are exactly equal for all 465 Val and 1,036 Test queries; final exported arrays need not be. The final invariant therefore checks raw localizer arrays for FlashVTG, submitted arrays for the four DETR-style backbones, and reports the FlashVTG calibration effect explicitly. This correction changes no prediction, metric, or model weight.
