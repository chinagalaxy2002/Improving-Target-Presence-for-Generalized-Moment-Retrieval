# Moment-DETR Table 2 deployment

Source: official GMR committed snapshot `ac78df9129a1153e74d4f75ad437a34fd770487b`, obtained with git archive (local working-tree research changes excluded). Original Moment-DETR repository cloned into upstream_original at `b7e553ac3b0c898ee6b85e03ee507c064eab89ca` for architecture reference. The official Moment-DETR implementation exposes both native and GMR existence-head variants, selected by use_exist_head. Neither variant uses S4 or CGP.

Runner: deploy.py. Python: /home/guoxiangyu/miniconda3/envs/gmr/bin/python. Training is sequential original then GMR in a single scheduler-managed Python process bound to physical GPU0. Persistent parent is tmux table2_scheduler_20261022. Each variant has an independent model initialization, optimizer, and output directory.

Data: original Standard train4138 (2002 negative), val465 (210 negative), test1036 (492 negative). Labels and features are read from the official local repository. Missing features fail an assertion. All naturally occurring negatives and every annotated window are retained. Max targets is effectively unlimited; observed maximum is six, below ten native detection queries. CLIP512 then SlowFast2304 then TEF2 gives2818 video dimensions; CLIP text512. Existing vectors aggregate approximately two seconds (example duration111 has56 vectors), so clip_length2/max_v_l75 preserve supplied feature timing; this does not assert that vectors themselves are1fps. The paper describes source frame sampling at1fps.

Protocol: seed2026 for Python, NumPy, Torch, CUDA and DataLoader generator/workers; deterministic CuDNN and CUBLAS workspace configured. No augmentation, QCD, query swap, background replacement, synthetic negatives, paraphrases, merges or feature regeneration. Dropout remains native architectural regularization. LR3e-5 per paper, native bsz8/eval_bsz4, 400epoch cap, early stopping50 validation checks, AdamW wd1e-4, stepLR400, grad_clip0.1, ten queries, encoder/decoder2layers. Official mr_only localization protocol is retained (no synthetic saliency labels).

Original variant: native classification and Hungarian span losses, including background classification supervision on retained negatives. GMR variant: backbone losses on positive pairs only and BCE existence loss on all pairs, coefficient1.0, following paper Sec4.1. The paper's no-negative-VMR statement conflicts with the released criterion's background CE when run on empty targets; the runner explicitly applies the paper's positive-only mask to GMR. No model architecture changes are made.

Validation uses all465 examples and the coordinator's pinned committed official evaluator. Selection is highest validation positive-query mAP, preserving original official selection criterion. Native best-checkpoint initialization changed from0 to negative infinity so the first checkpoint is always saved. No test data loaded during optimization or checkpoint selection. Only after training finishes, selected checkpoint SHA256 and fixed threshold0.4 are recorded, strict checkpoint reloading precedes one final test inference/evaluation. Original scores come from foreground confidence; GMR existence scores gate official generalized metrics. Raw proposals remain available for positive localization metrics as in the official evaluator. Native per-video span conversion, clipping and two-second rounding are applied.

Smoke covers positive and negative forward/backward/optimizer steps for both models, finite losses and gradients, batch8 peak GPU allocation, strict checkpoint reload, validation prediction format and official evaluation. v2 smoke reports are in each variant's smoke.json; smoke metrics are diagnostic only. Peak allocations: original217.04MiB, GMR218.08MiB; scheduling reservation3000MiB includes CUDA context and margin. v1 smoke was superseded before training to preserve native baseline negative CE and use coordinator's pinned evaluator; both logs are retained.

Run state: effective_config.json, environment.json, train log, latest/best validation predictions, validation metrics, resumable last.ckpt (optimizer/scheduler/all RNG states/DataLoader generator), best.ckpt, frozen_selection.json, test_predictions.jsonl and test_metrics.json are produced by deploy.py. Training can resume the interrupted current variant safely from last.ckpt; completed runs must not be restarted in place.

Acceptance remains unevaluated until final test artifacts exist. Diagnostic tolerance is2 absolute percentage points on localization/G-mIoU metrics; all eight paper metrics, including AUROC/Rej-F1, require inspection. No reproduction success is claimed from training launch or smoke metrics.
